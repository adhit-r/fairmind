# FairMind v2.1.0-alpha.1: P0 trustworthy control plane

**Release status:** internal, default-off prerelease

**Release date:** 2026-08-30

This is a P0 trust-foundation release. It packages the completed control-plane
and frontend/design checklists without claiming an executable evaluation
product, compliance outcome, certification, automatic approval, or automatic
enforcement.

## Included

- Versioned target, suite, run, execution-envelope, and Passport v2 evidence
  identity.
- Signed-evidence admission, replay/scope/expiry checks, trust policies,
  issuers, verification keys, and independently gated administration.
- PostgreSQL-authoritative operational freshness, idempotency generations,
  append-only audit records, review/decision authority, and audited,
  decision-only owner and exact-run delegated separation overrides.
- Explicit user-interface state for evidence trust, freshness, reviewer state,
  and governance-decision state.
- Explicit unavailable states for LLM judge, LLM testing, explainability,
  modern-bias, and multimodal packs.
- A canonical P0 documentation site and source guide set generated through
  Docs Forge, including an applicability-first EU AI Act evidence crosswalk.
- A truth-aligned public website boundary with no placeholder analytics or
  unverified access-form data collection.

## Not included

- Sandboxed workers or worker-issued credentials.
- Independently calibrated predictive, LLM, agent, code, vision, image, audio,
  video, or multimodal evaluators.
- Pre-deployment, realtime, or post-deployment assurance workflows.
- Retention/export lifecycle proof, a production deployment claim, a legal
  compliance determination, certification, automatic approval, or automatic
  enforcement.

## Release gates

The `P0 release gates` workflow validates this release surface on pull
requests, `main`, and manual dispatch:

1. P0 backend contract tests and backend boundary/archive guards.
2. Frontend unit tests, TypeScript typecheck, production build, workbench
   browser checks, unsupported-pack checks, and Assurance V2 child-gate checks
   in both fail-closed and enabled-preview configurations.
3. Docs Forge content validation, runtime dependency audit, TypeScript check,
   and production build for all nine canonical P0 guides.
4. Public website runtime dependency audit and static production build on
   Node 22.12.
5. Native PostgreSQL 14 P0 decision, review, freshness, audit, and migration
   checks against a disposable CI database.

Ordinary governance decisions intentionally avoid the 013l-only delegated
grant column when no grant is present. This preserves integrity verification
against historical 013b-013k schemas while requiring 013l for every delegated
override.

The tag workflow re-runs those checks for the exact `v2.1.0-alpha.1` tag and
creates a GitHub prerelease only if the tag points to a commit containing this
committed release note. It uses the GitHub-provided token only; no deployment or signing
secret is assumed.

## Operating boundary

Routes that mutate trust, admission, review, and governance decision state are
default-off and must remain inside a controlled internal environment. The
frontend's visible evidence state is supporting information, not a statement
that an unavailable evaluator executed or that an organization has achieved a
legal or standards-based outcome.

For the detailed roadmap and evidence references, see the
[2027 assurance roadmap](../superpowers/plans/2026-07-19-fairmind-2027-ai-assurance-todo.md).
