What FairMind is

An open-source AI assurance workbench for models and agents.

It turns governance frameworks into controls, collects evaluation evidence, and gates releases. It keeps an AI system, its tests, evidence, risks, remediation and approvals in one reviewable record.

The question
May this system ship, and what is the evidence?

The question FairMind answers for a release.

The rule
An evaluation result is evidence for a decision, never the decision itself. A person decides.

A pending release request is decided by someone other than the person who asked.

The lifecycle, as it works today
StageQuestionWhat it does today
01OnboardWhich system are we governing, and under which frameworks? Register a system, or discover it from MLflow, GitHub or the Hugging Face Hub and promote it from a review queue.
02AssessWhat was tested, how, and against which threshold? Evaluations run on uploaded files, as behaviour tests against your live system, as configuration audits of your agent platform, or on results from your own sandbox, drills and detectors. Results are stored as measured evidence.
03GovernWhich evidence and risks bear on each control? Policies mapped to framework controls, evaluated live, counted as evidence. Evidence shows where it came from and how much it counts.
04RemediateWhat must change, who owns it, and did the retest pass? Findings, owners and retests.
05OperateWhat changed after release? You push monitoring snapshots on your schedule, for example fairmind monitor in cron. Stale snapshots are flagged and sustained drift opens a finding.

Release gate

Five checks, three verdicts

Fairness, data governance, human oversight, monitoring and environmental. Each reads the newest evidence on file.

goconditional_gono_go
  • The verdict comes from the system's risk tier and the overall confidence across the five checks.
  • Failing blocking policy rules force no_go. A measured fairness failure never passes as a plain go.
  • The gate informs the decision; it never makes it. A person approves or rejects a release request, and approval is refused while critical findings are open.
Evidence model

A record an auditor can check

  • Evidence Passport. Bring your own evaluator: the passport carries subject, evaluator and metric versions, threshold, artifact digest, result and limitations, and enters the same review, mapping and gate.
  • Strength. Measured evidence (FairMind ran it) counts for more than attested evidence (a person stated it).
  • Tamper-evident. A hash-chained run ledger; chain state is shown on the run page.
  • Auditor pack. The gate per framework clause, inspection packs, a read-only auditor link, and offline verification with fairmind verify.

What FairMind is not

  • Not a certification. No compliance certificate, automatic approval or "verified" badge. Readiness and evidence only.
  • Not a runtime guardrail. It assesses systems; it does not sit in the request path.
  • Not a sandbox. Engines run inside the backend; uploaded model files are inspected, never executed.

Alpha: partly done or not built yet

  • Agent steps draft a workflow step when a person asks, and write to the ledger only.
  • 21 agent, attack and detector evaluations judge a results file you produce in your own sandbox; FairMind computes the metric but does not run the scenario.
  • Monitoring takes the snapshots you push; FairMind does not pull data.
  • Catalogue workflows: 86 of 90 are marked proposed until organisations run them.
  • Not built: automatic workflow starts (a person starts every run) and sandboxed evaluation workers.
