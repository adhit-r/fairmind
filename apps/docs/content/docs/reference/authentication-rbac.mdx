FairMind supports internal JWT authentication and configuration-dependent Neon or Authentik paths.

## Token model

JWT payloads can include user identity, roles, permissions, token type, optional scope, and session ID. The frontend stores bearer and refresh tokens in browser storage.

## Three role scopes

Do not combine the current role vocabularies into one enterprise matrix.

| Scope | Roles | Storage boundary |
| --- | --- | --- |
| Core JWT | admin, analyst, viewer, api_user | Token and core auth configuration |
| Compliance | compliance_admin, compliance_manager, compliance_auditor, compliance_viewer | Current manager assignments are process-memory based |
| Organization | owner, admin, member semantics, plus frontend role labels | Database-backed membership and organization checks |

## Production cautions

- Enable and verify the intended identity provider before deployment.
- Development contains authentication bypasses for selected paths.
- The current login route includes demonstration behavior and must not be described as production authentication.
- Browser tokens are not HttpOnly-cookie sessions.
- Organization middleware supplies context, while route decorators remain responsible for enforcement.
