Remediation closes the loop between a finding and the decision that follows it.

## Create the task

1. Open the risk or evidence record that needs action.
2. Create a remediation task.
3. Record the source type and linked risk.
4. Assign an owner, priority, due date, and status.
5. Mark whether a retest is required.

## Complete the technical work

Use the remediation record to track the action, not to store a rewritten history of the original result. Keep evidence from before and after the change as separate records.

## Attach the retest

1. Run the same evaluator against the new subject version when possible.
2. Preserve the method and threshold so the comparison is meaningful.
3. Attach the new result.
4. Link it as the superseding rerun.
5. Record the reviewer decision.

FairMind blocks completion when a required retest has not passed.

## Evidence basis

Task fields and retest state are defined in `apps/frontend/src/lib/api/hooks/useRemediation.ts`, the remediation page, and the corresponding AI-governance routes.
