---
title: Govern your first agent
description: Connect your agent platform, test the agent's behaviour and configuration, and read the release gate clause by clause.
---

<Status state="shipped">Works today for agents on Claude Managed Agents and for any agent FairMind can call over the web.</Status>

By the end you have measured evidence on an agent's behaviour and its platform configuration, a release verdict, and the same verdict read against the EU AI Act.

FairMind tests an agent two ways. **Behaviour tests** send it adversarial inputs and have your organisation's model judge the answers. **Configuration audits** read the platform the agent runs on, read-only, and check tool permissions, memory and sandboxing.

<Steps>
<Step>
### Register the agent

In **Inventory › AI systems**, press **Register systems** and register the agent: name, owner, risk tier and the frameworks that apply. The risk tier sets how much evidence a `go` needs. See [Register a system](/docs/journeys/register-system).
</Step>

<Step>
### Set up the judge

Behaviour tests need a model to judge the agent's answers. Under **Settings › AI provider**, choose one of the supported providers and enter its key. The key is encrypted at rest and never shown again.
</Step>

<Step>
### Tell FairMind how to call the agent

In the agent's system file, set **how FairMind calls this AI system**: the address it answers on and any access value it needs. Behaviour tests send their inputs there.
</Step>

<Step>
### Connect the agent platform

For configuration audits, open **Testing › Agent audits**, paste a **Claude Managed Agents** key into **API key**, press **Save key**, then **Test connection**. FairMind reads agents, environments, vaults, memory stores, deployments and recent sessions with read-only calls. Vault credential values are write-only on the platform, so FairMind never sees them. Only owners and admins can change this setting.
</Step>

<Step>
### Run the evaluations

Open [Testing › Evaluations](/docs/app/testing/evaluations), search for the behaviour tests you want (for example *prompt injection* or *system prompt leakage*) and press **Open to run** on each, choosing the agent as the system. For the configuration audits, open [Testing › Agent audits](/docs/app/testing/agent-audits) and press **Run** on a check, such as data exfiltration through agent tools.

Each run is stored as **measured** evidence on the system with its method, inputs and the judge used. Passed, failed and insufficient results are all kept; an insufficient run says what was missing.
</Step>

<Step>
### Read the gate

Open the agent's system file. **Release gate** shows the verdict (go, conditional go or no go), the confidence and one bar per check. The **Requirements** tab reads the same gate clause by clause for each framework, such as the EU AI Act. A mapping means the evidence is relevant to the clause, not that the clause is satisfied.
</Step>

<Step>
### Decide

Open the system's page, review the evidence and findings, and request a release decision. A reviewer approves or rejects it. Approval is refused while critical findings are open; fix them first with [Fix and retest](/docs/journeys/remediation-retest).
</Step>
</Steps>

## What you have now

- Measured evidence for each behaviour test and configuration audit, with its provenance.
- A release verdict and confidence, and the same verdict read against the EU AI Act.
- A decision record a reviewer signed off, or the findings that block one.

## Find more evaluations

There are 10 configuration audits and over 20 behaviour tests. In [Evaluations](/docs/app/testing/evaluations), search for *agent* and switch **Engine** to **All** to see every one.
