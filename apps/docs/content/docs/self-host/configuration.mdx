Backend settings load from `.env`. Unknown keys are ignored, so spelling errors can silently leave a default active.

## Core settings

| Purpose | Variables |
| --- | --- |
| Environment | `NODE_ENV`, `ENVIRONMENT`, API title/version, CORS origins |
| Database | `DATABASE_URL` and pool settings |
| Cache | `REDIS_URL` |
| Identity | JWT, Neon, and Authentik settings |
| Files | upload, dataset, and model-cache directories and limits |
| Storage | S3 endpoint, bucket, region, and credentials |
| Email | SMTP, SendGrid, SES, or Resend configuration |
| Observability | logging, audit retention, and Sentry |
| Evaluators | provider model, timeouts, concurrency, and compliance encryption |

Use `apps/backend/.env.example` as the inventory. Never copy development placeholders into production.

## Frontend API routing

Direct browser calls:

```bash
NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
```

Same-origin Next.js proxy:

```bash
BACKEND_INTERNAL_URL=http://localhost:8000 npm run dev
```

## Assurance V2 gates

Every Assurance V2 route is unmounted unless `ASSURANCE_V2_ENABLED=true` and its own gate is also `true`. All default to `false`. Turn on only the gates a deployment needs, as an approved change.

| Gate | Mounts |
| --- | --- |
| `ASSURANCE_V2_ENABLED` | No routes on its own; required by every gate below. It also changes startup and legacy behavior, described below |
| `ASSURANCE_V2_TARGET_VERSIONS_ENABLED` | Target-version routes |
| `ASSURANCE_V2_SUITE_VERSIONS_ENABLED` | Suite-version routes |
| `ASSURANCE_V2_PLANS_ENABLED` | Plan create, activate, and preflight |
| `ASSURANCE_V2_RUNS_ENABLED` | Run create and read |
| `ASSURANCE_V2_EVIDENCE_SUBMIT_ENABLED` | Signed Evidence Passport V2 submission |
| `ASSURANCE_V2_EVIDENCE_LINK_ENABLED` | Linking a verified admission |
| `ASSURANCE_V2_EVIDENCE_IMPORT_ENABLED` | Unverified report import |
| `ASSURANCE_V2_EVIDENCE_REVIEW_ENABLED` | Four-eyes evidence review |
| `ASSURANCE_V2_GOVERNANCE_DECISION_ENABLED` | Governance decisions |
| `ASSURANCE_V2_SEPARATION_OVERRIDE_ENABLED` | Owner override and delegated grants; also needs the decision gate |
| `ASSURANCE_V2_EVALUATOR_CATALOG_ENABLED` | Evaluator registration administration |
| `ASSURANCE_V2_TRUST_ADMINISTRATION_ENABLED` | Issuer, signing-key, and trust-policy administration |
| `ASSURANCE_V2_ARTIFACT_UPLOAD_ENABLED` | Evaluation input artifact upload to the write-once S3 store; also needs the `EVALUATION_ARTIFACT_*` settings below |

### Evaluation artifact store

Uploads go to S3 through a dedicated IAM user that holds only `s3:PutObject` and `s3:GetObject` on the configured prefix, never the general `AWS_ACCESS_KEY_ID`. None of these has a default; with any of them unset, uploads return `503 artifact_store_unavailable`.

| Setting | Meaning |
| --- | --- |
| `EVALUATION_ARTIFACT_S3_BUCKET` | Bucket name |
| `EVALUATION_ARTIFACT_S3_PREFIX` | Key prefix ending in `/`; objects are stored at `<prefix>sha256/<digest>` |
| `EVALUATION_ARTIFACT_S3_REGION` | Bucket region |
| `EVALUATION_ARTIFACT_AWS_ACCESS_KEY_ID`, `EVALUATION_ARTIFACT_AWS_SECRET_ACCESS_KEY` | The dedicated IAM user's key |
| `EVALUATION_ARTIFACT_S3_ENDPOINT_URL` | Optional; leave unset for AWS |
| `EVALUATION_ARTIFACT_MAX_BYTES` | Largest accepted upload, default 10 MiB |

### What the master switch does on its own

Turning on `ASSURANCE_V2_ENABLED` has two effects even when every child gate is off:

- **Startup integrity checks.** The backend binds a trusted `search_path` for the schema named in `ASSURANCE_MIGRATION_SCHEMA`, then refuses to start unless the bundled migration checksums, the migration ledger, and the installed catalog fingerprint all match the frozen values in `apps/backend/config/migration_integrity.py`.
- **Legacy evaluation writes stop.** The older evaluation service rejects plan create, plan activate, run create, and Passport linking with `409 contract_upgrade_required`, and its preflight reports that a run cannot be prepared.

### Startup requirements

With the master switch on, startup fails closed unless:

- the database is PostgreSQL. Any other database fails at startup with `unsupported database dialect for assurance v2`, so Assurance V2 as a whole, including reviews, imports, freshness, and decisions, is PostgreSQL-only;
- `ASSURANCE_MIGRATION_SCHEMA` names an existing schema;
- migrations `013` to `013n` are applied and the migration ledger matches;
- the installed catalog matches the frozen fingerprint for the PostgreSQL major version (14 or 18) in `FROZEN_POSTGRESQL_ASSURANCE_CATALOGS`.

<Callout type="warn" title="Known limitation: PostgreSQL 18 and Neon">
The frozen PostgreSQL 18 fingerprint is still the `013j` measurement, and it includes the Neon project role graph. On Neon or PostgreSQL 18 with `013k` to `013n` applied, startup with the master switch on fails closed until the fingerprint is re-measured there. Adding or removing a Neon project role also changes the fingerprint. See `apps/backend/migrations/upgrade_paths/README.md`.
</Callout>

See [Permissions and separation](/docs/reference/permissions-and-separation) for who can use each route.

## Production mode

Production mode depends on `NODE_ENV=production`. Setting only `ENVIRONMENT=production` is not equivalent. Production validation rejects short secrets and known development placeholder values.

## Evidence basis

Settings are defined in `apps/backend/config/settings.py` and inventoried in `apps/backend/.env.example`. Frontend proxy selection is implemented in `apps/frontend/src/app/api/proxy/[...path]/route.ts`.
