---
title: SDK and MCP server
description: Ask FairMind whether a system may ship from Python code or from a coding agent, without opening the app.
---

Engineers and coding agents should not need a form to reach FairMind. The Python SDK wraps the API in a handful of typed calls, and the MCP server exposes the same calls as tools an agent can use. Both read the same two environment variables as the CLI.

## Set up

1. Create an API key once, as a user who belongs to the system's organisation: `POST /api/v1/auth/api-keys` with a name.
2. Export it where the code or the agent runs:

```bash
export FAIRMIND_API_URL=https://fairmind.example.com
export FAIRMIND_API_KEY=...
```

Never put the key in a config file or a repository. `FAIRMIND_API_URL` defaults to `http://localhost:8010`.

## Python SDK

Install from PyPI (from a checkout: `pip install ./apps/sdk`):

```bash
pip install fairmind
```

```python
from fairmind import FairMind, FairMindError

fm = FairMind()  # reads FAIRMIND_API_URL and FAIRMIND_API_KEY

system = fm.systems()[0]["id"]
run = fm.run_fairness(
    system, "predictions.csv",
    outcome="repaid", prediction="approved", attributes=["gender", "region"],
)
print(run["gate"]["verdict"], run["gate"]["confidence"])

try:
    gate = fm.gate(system)
except FairMindError as err:
    print(err.status_code, err.message)
```

| Method | What it does |
| --- | --- |
| `systems()` | The AI systems your key can see |
| `gate(system_id)` | Verdict, confidence and the state of each check |
| `clause_map(system_id, frameworks=None)` | The gate read per framework clause; `frameworks` filters by catalogue key such as `EUAIA` |
| `seals(system_id)` | Decision seals, each verified against the evidence as it is now |
| `inspect_csv(system_id, path)` | Columns of a CSV and a suggested mapping |
| `run_fairness(system_id, path, *, outcome, attributes, prediction=None, score=None, favorable_label=None)` | Run the metrics and store measured evidence |
| `run_monitoring(system_id, path, *, attributes, prediction=None, score=None, favorable_label=None)` | Compare recent decisions with the latest fairness run |
| `attest(system_id, check, statement, reference=None)` | Record a person's statement that a check is satisfied |

Every failure raises `FairMindError` with the HTTP `status_code` (`None` when the server was unreachable) and the server's message.

## MCP server

`fairmind-mcp` serves nine tools over stdio: `list_systems`, `release_gate`, `clause_map`, `run_fairness_test`, `record_monitoring_snapshot`, `attest_check`, `list_evaluations`, `describe_evaluation` and `run_evaluation`. Each returns a compact text summary plus the full response as structured content. The CSV path in `run_fairness_test` and `record_monitoring_snapshot` is a path on the machine running the server, which is normally the developer's own.

Add it to Claude Code from a checkout:

```bash
claude mcp add fairmind -- uvx fairmind-mcp
```

The server inherits `FAIRMIND_API_URL` and `FAIRMIND_API_KEY` from the shell. The `apps/mcp` README has the `.mcp.json` and Claude Desktop configurations, which also pass the environment through without containing a key.

Then ask the agent in plain language: "May the credit-scoring system ship?" It lists the systems and reads the gate. "Run a fairness test on `holdout.csv` for gender and region" uploads the file and returns the metrics and the updated verdict.

`attest_check` writes manual evidence under your name. An attestation counts for less than a measured result, so the gate shows the check as attested, never proven, and the tool tells the agent to use only statements you gave or confirmed.
